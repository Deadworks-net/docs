### CAI_BaseNPC.Create() {#create}

Creates and spawns an NPC by its VData subclass name, such as `neutral_trooper_strong` or `npc_boss_tier1`. Returns null if the name is not an NPC subclass.

**Signature**

```csharp
public static CAI_BaseNPC? Create(string designerName, Vector3 position, int team = 0, Vector3? angles = null)
```

**Parameters**

- `designerName`: The subclass name.
- `position`: Where the NPC appears.
- `team`: The team number. 0 leaves the NPC's default.
- `angles`: The way it faces (pitch, yaw, roll). Null faces along +X.

**Notes**
Deadlock's NPCs take their stats from VData, so a class name without one (`npc_trooper_neutral`) returns null: such an NPC crashes the server when it spawns. For lane troopers use [`CNPC_Trooper.Create`](/api-reference/entities/cnpc_trooper#create), which also gives them a lane.

### CAI_BaseNPC.MoveTo() {#moveto}

Sends the NPC to `goal`, the same order as the `npc_go` console command, but with no cheats or NPC selection needed.

**Signature**

```csharp
public void MoveTo(Vector3 goal, bool run = true, float tolerance = 0f)
```

**Parameters**

- `goal`: Where to go.
- `run`: Run instead of walking.
- `tolerance`: How close counts as arrived. 0 is what `npc_go` uses.

**Notes**
The move can't be interrupted: the NPC ignores enemies and damage until it arrives or the path fails, unless the `npc_go_allow_interrupt_by_ai_conditions` convar is on. It then goes back to its own behaviour, which for a lane trooper means walking back to its lane. To keep an NPC following a moving target, call this again every half second or so. The goal doesn't need to be on the navmesh.

### CAI_BaseNPC.SetSchedule() {#setschedule}

Switches the NPC to the named schedule now, such as `SCHED_IDLE_STAND`, the way the game's own "set schedule" task does. Returns false if the NPC refuses it.

**Signature**

```csharp
public bool SetSchedule(string name)
```

**Notes**
The schedule runs until it finishes or something interrupts it (a new enemy, damage...), and then the NPC picks its next one as usual; `IDeadworksPlugin.OnNpcSelectSchedule` can steer that choice. A name the NPC's class has no schedule for runs `SCHED_IDLE_STAND`, and the game logs "No CASE for Schedule Type".
