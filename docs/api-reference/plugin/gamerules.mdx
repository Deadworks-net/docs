### GameRules.MatchStartOnAnyMap {#matchstartonanymap}

Gives every map the match start dl_midtown has: a countdown in base, then everyone launched down their lane's zipline (choose lanes with [`CCitadelPlayerController.AssignedLane`](/api-reference/entities/ccitadelplayercontroller#assignedlane)). Off by default, when only dl_midtown starts that way and any other map goes straight into the match with everyone in base.

**Signature**

**Notes**
On a server without a matchmaking lobby the countdown also needs `citadel_match_intro_force_enabled 1`, the same as on dl_midtown. The setting lasts across map changes, so turn it off again when your plugin unloads.

### GameRules.SetWaitingForPlayersRoster() {#setwaitingforplayersroster}

Overrides the roster used by the engine's internal WaitingForPlayersToJoin readiness check. The engine's own roster is populated by matchmaking/party data, which is always empty on a direct-connect dedicated server, so the check (and the counts it caches into the client-networked HUD fields) reflects a real target instead of always reading empty/zero. The state advances once `readyCount` &gt;= `totalCount`. Pass a `totalCount` of 0 to disable the override and restore the engine's native behavior. This is native global state, not a field on the game rules entity; it is persists across map changes and is cleared on plugin unload.

**Signature**

```csharp
public static void SetWaitingForPlayersRoster(uint readyCount, uint totalCount)
```

### GameRules.SetGameStartTime() {#setgamestarttime}

Sets m_flGameStartTime, which the match clock (`GameClock` and the client's HUD timer) is computed relative to. On a server without real matchmaking, this field is never reset once the pregame flow actually reaches GameInProgress, so the clock counts from map load instead of from when the match really starts.

### GameRules.SetGameStateEndTime() {#setgamestateendtime}

Sets m_flGameStateEndTime, which drives the client's countdown display for states that show one (e.g. PreGameWait's "Game starting..."). The engine's own ChangeGameState only writes a real value here when an internal eligibility check passes; on servers where that check never passes, the field is left at a sentinel and the client shows no countdown number.
